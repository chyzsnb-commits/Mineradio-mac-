# Mineradio 2.0 公开发布审计

审计日期：2026-07-24

## 结论

当前分支可作为 **2.0.0 双架构技术候选包**，但在完成签名、公证、隐私联系信息和音乐平台授权确认前，不应标注为“已完成合规审查”的正式公开版本。

## 已完成

- 正式产品身份：`mineradio`、`2.0.0`、`com.mineradio.desktop`，`internalBeta=false`。
- 汽水音乐后端、登录桥、本地 Cookie 数据库读取、Token/Cookie 导入、模拟客户端扫码与音频解密器已从公开分支删除。
- 登录凭据手动导入、导出在公开版关闭；支持平台的本机会话与 Spotify token 使用 Electron `safeStorage` 加密保存。
- 网易云、QQ 音乐和酷狗的官方登录结果由 Electron 主进程直接交给本地服务验证和保存，不再经过公开版禁止的手动 Cookie 导入 HTTP 接口，也不向渲染进程返回原始 Cookie。
- 旧版明文 Cookie 与 Spotify 凭据只在成功改写为 `safeStorage` 密文后继续使用；加密或持久化失败时登录桥返回失败，不静默伪装成已保存。
- 登录页和搜索栏不包含汽水入口；旧队列中的汽水曲目按“音源已移除”处理，不再串到其他平台接口。
- 底部控制条 15 个按钮恢复即时功能说明；3D 歌单架滚动阈值从 `190` 调到 `140`，运行验收确认向下仍为 `+1`、向上仍为 `-1`。
- 登录卡片、右上角账号胶囊和账号详情不再展示可能误判的普通/VIP/SVIP 等级；仅移除界面标签，后台播放权限判断没有删除。
- 音质切换使用单条串行换流链，保留当前歌词、播放位置和听歌会话；快速点击合并到最后一次选择，失败恢复旧流，音质通知按同一张卡替换。
- 本地服务默认仅监听 `127.0.0.1`，并拒绝外部网页 Origin 调用本地 API。
- 匿名遥测在正式版完全不启动；崩溃记录、摄像头画面、麦克风音频和 AI 分轨结果不上传。
- 增加摄像头/麦克风用途说明、隐私说明、第三方组件说明和 MediaPipe Apache 2.0 许可证。
- 生产依赖执行 `npm audit --omit=dev` 后为 0 个已知漏洞。
- 已生成并验证 Apple Silicon arm64 与 Intel x64 DMG。

## 2.0 登录回归修复

首批 2.0 候选包存在登录回归：官方登录窗口成功取得会话后，渲染进程仍调用 `/api/login/cookie`、`/api/qq/login/cookie` 或 `/api/kugou/login/cookie`；这些手动导入接口按公开版策略返回 403，因此网易云、QQ 音乐和酷狗表现为“扫码成功但登录不上”。

修复后，官方窗口取得的会话只在 Electron 主进程和本地服务之间流转，并通过 `safeStorage` 加密落盘；渲染进程只收到白名单内的去敏账号状态。手动 Cookie 导入与导出仍保持关闭，汽水音乐仍保持删除。自动回归覆盖官方登录桥、成功与失败结果均不泄漏 Cookie、三平台前端不再调用手动导入接口、旧明文登录态安全迁移，以及公开版继续隐藏手动导入与汽水入口。

## 2.0 音质切换回归修复

首批音质切换实现复用了完整切歌流程，并且每次点击都会并发启动一条新任务。高音质不可用时，QQ 自动兼容还会递归启动新的切歌，造成任务互相抢占切歌令牌、当前音频源提前清空、进度停在 `0:00`、通知堆叠以及歌词舞台重复重建后留下巨型残影。

修复后，当前音频会持续播放到新音质地址确认可用；同一首歌的快速选择只串行处理当前项和最后一项，中间选择不执行。换流只替换音频源并恢复原时间，不再调用完整切歌、歌词重建、歌架重建或听歌会话重置；新流启动失败时恢复旧流。专项自动测试和 Electron 运行模拟确认原时间 `57s` 保留、歌词节点数不变、歌词重建调用为 0、音质通知只保留 1 张，底栏音质与红心按钮在桌面/全屏布局下实际间距为 `13–20px`。

## 汽水音乐判断

原实现包含读取官方客户端 Cookie 数据库、要求用户粘贴会话 Cookie/Token、模拟官方客户端请求及解密受保护音频等行为。免责声明不能消除这些行为的账号安全、平台协议、隐私和内容授权风险，因此 2.0 公开分支采取的是删除，而不是继续保留后加提示。

## mineradio.cn 分发核对

- Apple Silicon 与 Intel DMG 均已实际挂载；镜像内包含 `Mineradio.app` 和指向 `/Applications` 的快捷方式，因此官网“打开 DMG，把 Mineradio 拖进应用程序”的步骤仍然适用。
- 官网现有 `xattr -cr /Applications/Mineradio.app` 与“系统设置 → 隐私与安全性 → 仍要打开”说明适用于当前未公证测试包，但不能替代正式公开发行所需的 Developer ID 签名与 Apple 公证。
- 官网当前“v1.1.3 起 Intel 与 Apple 芯片同一安装包”的说明不适用于 2.0。正式上线前应改为两个明确入口，并提示用户按“Apple Silicon（M 系列）”或“Intel”选择对应 DMG。
- 官网当前 Mac 下载卡仍显示 `v1.1.3` 并指向旧下载目录；在 2.0 DMG 尚未上传到正式下载地址前，不应把该入口标记为 2.0。
- 本机 `/Applications/Mineradio.app` 已替换为 arm64 2.0.0；其 `app.asar` 与构建目录、挂载后的 arm64/x64 DMG 四方 SHA-256 均为 `7fc71506f0dfc60bd76ed0702d200230380540a0f1e8ee7b3b4d0a450884c953`。旧安装版已移入 `.noindex` 备份并取消 `.app` 后缀，系统只识别 `/Applications/Mineradio.app`。

## 正式公开前的阻塞项

1. **Apple 签名与公证**：本机没有有效 Developer ID Application 证书；当前 DMG 未签名、未公证，只适合内部验收。
2. **音乐内容与平台授权**：网易云、QQ、酷狗等接入包含非官方或未在仓库中提供授权证明的接口/播放链路。发布者必须确认平台接口授权、内容播放权、商标使用和用户账号会话使用范围；无法确认时应在正式公开版关闭对应联网播放能力。
3. **隐私主体信息**：发布下载页前补充运营者名称、联系方法、数据删除入口和永久隐私政策网址。
4. **第三方许可终审**：按最终 `app.asar` 和 `node_modules` 清单保存完整许可证/NOTICE，并确认 GSAP 等非 MIT 组件的分发范围。
5. **真机验收**：Intel Mac 仍需实机启动、搜索、播放、歌词、摄像头手势、麦克风唱歌模式和 AI 分轨验收。
