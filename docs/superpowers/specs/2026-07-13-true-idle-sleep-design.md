# 主循环真正休眠与 idle guide 停止空转设计

## TL;DR

前台无播放、无加载、无交互、无歌架动效时，主循环不再让 `requestAnimationFrame` 按屏幕刷新率持续唤醒，而是用 500ms 定时器实现真正约 2 次/秒的空闲循环。idle guide 背景功能关闭且没有歌架引导时不启动循环，深后台强制停止；播放、交互、视觉引导和回到前台会立即唤醒。

## 基线与目标

- 已测基线：空闲 3 秒内 `animate` 执行 337 次，约 112 次/秒，但真正渲染约 2 FPS。
- 已测基线：禁用的 idle guide 仍约每 140ms 清理一次大画布，约 7 次/秒。
- 目标：前台空闲主循环约 2 次/秒；可见失焦约 15 次/秒；idle guide 无内容或深后台时 0 次/秒。
- 正确性底线：播放、换源、切歌、输入、拖动、歌架、桌面歌词和壁纸模式不能因休眠漏帧或延迟恢复。

## 方案选择

1. **按状态使用 timeout 休眠（采用）**：播放和交互继续使用 rAF；空闲 500ms，可见失焦约 66ms，深后台沿用现有 250-1500ms。收益明确，状态变化可立即唤醒。
2. **继续高频 rAF，只在函数内跳帧（不采用）**：视觉风险低，但正是当前每秒唤醒 112 次的根因。
3. **完全事件驱动，空闲无限期停止（不采用）**：理论功耗最低，但网络加载、异步封面和自动状态变化可能没有事件唤醒，容易出现界面不更新。

## 主循环调度

- `scheduleNextMainLoopFrame()` 根据当前状态选择：
  - 深后台：保留现有 250/1000/1500ms。
  - 窗口可见但失焦：约 66ms，对齐现有 15 FPS 策略。
  - 窗口聚焦但空闲：500ms。
  - 播放、加载或交互：rAF，保持现有流畅度。
- `markRenderInteraction()` 在记录交互时立即取消休眠定时器并请求一帧。
- 窗口聚焦、可见性恢复以及音频播放事件立即唤醒。
- 空闲判定继续保留 `playToggleBusy` 防护，避免加载/换源期间停启 WebGL 导致黑屏。

## idle guide 生命周期

- 记录 timeout 和 rAF 两种句柄，支持统一停止，避免已有 rAF 无法取消。
- `IDLE_GUIDE_BACKGROUND_ENABLED=false` 且歌架提示值为 0 时，不启动下一帧，不再每 140ms 清画布。
- 歌架引导或悬停提示开始时显式唤醒；淡出到 0 后自行停止。
- 深后台立即取消 timeout 和 rAF；回到前台时仅在确有内容需要绘制时恢复。
- 不删除 idle guide 或歌架提示代码，视觉功能和以后重新启用背景的能力保留。

## 验证

- 测试先模拟调度状态，确认空闲 500ms、失焦约 66ms、播放/交互为 rAF、深后台沿用原延迟。
- 测试交互会取消休眠并立即请求 rAF。
- 测试 idle guide 在禁用且无提示时不安排下一帧，深后台取消所有句柄，提示激活时可唤醒。
- `npm run check`、全部相关前端文件语法检查、`git diff --check`。
- Electron 实机必须使用假摄像头参数，对比修改前后空闲回调与 CPU；播放和交互恢复需手动验证。

## 搜索预算

最多比较 2 个安全变体：空闲 500ms 与空闲 350ms。若 500ms 在交互唤醒后无可见延迟，优先选 500ms；若出现明显恢复延迟才考虑 350ms。任何黑屏、播放视觉延迟或自动状态不更新都直接淘汰该变体。
