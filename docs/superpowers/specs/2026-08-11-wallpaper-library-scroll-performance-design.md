# Windows 壁纸库滚动性能

## 目标

Windows 壁纸库存在数百条远程图片和视频记录时，滚动必须保持流畅，同时保留现有网格、滚动条、卡片点击、预览和详情行为。

## 根因与取舍

首轮渲染会为每张图片和视频直接设置媒体地址，视频还预读元数据；304 条记录会并发触发大量网络、解码和合成工作。滚动容器也没有明确隔离，卡片悬停的位移和阴影在连续滚动时会增加重绘压力。

采用渐进挂载而不是虚拟列表：`IntersectionObserver` 以网格作为根节点，只为可视区及其上下 280px 内的卡片设置媒体 `src`。图片使用原生懒加载和异步解码，视频初始 `preload="none"`。这样保留现有 DOM、搜索、排序、焦点和详情状态，避免虚拟列表改变卡片点击和预览生命周期。

滚动层增加绘制隔离与合成提示；滚动进行时临时移除卡片的位移过渡和重阴影，停下 180ms 后自动恢复。滚动条继续保留。

## 验证

- 专项测试检查图片、视频、观察器、被动滚动监听和滚动低开销样式。
- 使用 304 条模拟记录的页面检查：首屏仅挂载 20 个媒体，滚动后增至 40 个，滚动态会正确进入和退出。
- 完整 `npm run check` 必须通过。
- 真实 Windows 服务下的远程网络、媒体解码与实际手感仍需人工验收，不能由模拟数据替代。
