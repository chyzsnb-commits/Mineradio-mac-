# 唱歌模式按需计算与麦克风省电设计

## TL;DR

唱歌模式开启但原唱为 100% 时，播放音频直接连接分析器和输出，不创建去人声 Worklet；只有原唱低于 100% 才启用频谱去人声。麦克风仅在唱歌模式开启、歌曲正在播放且窗口不在深后台时采集，暂停、无歌曲、播放结束或进入深后台时立即停止，恢复播放和前台后自动重开。

## 基线与目标

- 基线：44.1kHz 音频模拟 1 秒，原唱 100% 与 0% 都执行 332 次 FFT，说明 100% 没有省掉频谱计算。
- 目标：原唱 100% 时不创建去人声链，去人声 FFT 为 0；低于 100% 时保持现有声音算法和调节能力。
- 目标：暂停、无歌曲、结束、错误或深后台时，麦克风 MediaStream 的所有 track 都停止，相关音频节点断开。
- 目标：恢复播放或回到前台时，如果唱歌模式仍开启，自动重新申请已授权的麦克风并接回可视化分析器。
- 不改唱歌模式按钮、滑块、歌词和视觉设计；不让麦克风进入扬声器；不修改摄像头默认状态。

## 方案选择

1. **音频图直接旁路（采用）**：100% 时 `source -> analyser`，低于 100% 时 `source -> vocalCutChain -> analyser`。节省完整 Worklet 调度和 FFT，复用现有防爆音重建。
2. **Worklet 内快速复制（不采用）**：处理器仍常驻音频线程，只跳过 FFT，节省不完整。
3. **仅暂停分析读取（不采用）**：Worklet 仍处理音频，无法消除根因。

搜索预算最多比较直接旁路与 Worklet 内快速复制两个变体。直接旁路只要声音连接、滑块切换和防爆音验证通过，就优先采用。

## 去人声链生命周期

- 新增统一判定：唱歌模式开启、音源不是 capture 回退、原唱低于 100% 时才需要去人声处理。
- `initAudio()` 根据判定选择直连或去人声链；直连时 `vocalCutChain` 必须为 `null`。
- 滑块跨越 100% 边界时调用现有 `rebuildAudioGraphNow()`，用 12ms 淡出和 20ms 淡入包住重接；同一侧调节继续只发 level，不重建。
- 从 100% 降到 99% 时先使用现有 biquad 回退，再异步加载 Worklet；加载成功且当前仍低于 100% 时才重建为频谱处理。
- 唱歌模式在 100% 开启时不预加载 Worklet；用户真正降低原唱后再加载。

## 麦克风生命周期

- `singingMicShouldRun()` 统一判断：唱歌模式开启、存在有效音频地址、媒体未暂停/未结束/无错误、当前不是深后台。
- 播放事件通过 `syncPlaybackStateFromAudioEvent()` 同步麦克风；窗口状态通过 `updateRenderPowerClasses()` 同步；切换唱歌模式也立即同步。
- 不满足条件时停止全部 track，断开 `micSource` 和 `micVisualNode`，清空引用。
- 满足条件时只允许一个 `getUserMedia()` 请求在途；使用序号处理“请求权限期间又暂停/关闭/进入后台”的竞态，过期请求返回后立即停止其 track。
- 权限失败后，本次唱歌模式开启期间不自动重复请求；关闭再开启唱歌模式才允许用户重试。
- 自动恢复不重复弹“麦克风已开”提示；用户首次开启且正在播放时保留一次提示。

## 测试与验收

- 自动测试音频图：100% 直连且不创建去人声链；99% 创建；跨越 100% 才重建。
- 自动测试麦克风状态：播放前台为 true，暂停、无 src、ended、error、深后台为 false。
- 自动测试异步竞态：请求未完成就暂停或进入后台，返回的 track 被停止且不接入；并发播放事件只发一个请求。
- 自动测试权限失败锁：失败后播放事件不重复申请，重新开启唱歌模式后可以重试。
- 运行 `npm run check`、相关前端语法检查和 `git diff --check`。
- Electron 实机只使用 `--use-fake-device-for-media-stream --use-fake-ui-for-media-stream`，确认播放/暂停/后台恢复和 100% 旁路；不调用真实摄像头或真实麦克风。

## 回滚

本任务独立分支和独立 commit。若自动恢复麦克风或音频重建出现回归，可单独回滚唱歌模式降载 commit，不影响 PR #30 的主循环休眠优化。
