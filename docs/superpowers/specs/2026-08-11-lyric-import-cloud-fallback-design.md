# 本地歌词导入与云盘回退设计

## 目标

本地导入歌曲继续自动读取同名 `.lrc` 和音频内嵌歌词；任何歌曲均可导入用户自己的 `.lrc`。网易云盘等无法用原始歌曲 ID 取词的曲目，在无可靠歌词时可进行严格的跨源匹配，但绝不把不可信候选显示为正确歌词。

## 已确认现状

- `desktop/local-music-library.js` 已读取同目录同名 `.lrc`，其次读取 `music-metadata` 暴露的 `common.lyrics`。
- 渲染端已拥有主进程歌词磁盘缓存，但缓存键是歌词 HTTP endpoint。云盘内部 ID 不是网易原曲 ID 时，这个键不能命中正确歌词。
- 手动导入 `.lrc` 目前没有 IPC、持久化记录或用户界面。

## 来源与优先级

既有的逐曲“自定义歌词”记录已保存歌词正文、更新时间和来源偏好；本轮复用该稳定存储而不新建第二份歌词库。播放时按以下优先级选择：

1. 已启用的用户导入歌词。
2. 本地曲库的同名 `.lrc` 或内嵌歌词。
3. 已缓存且与当前歌曲指纹关联的自动歌词。
4. 平台原始歌词接口。
5. 仅当原始接口没有可用歌词时，严格跨源候选匹配后的歌词。
6. 标题回退和“导入歌词”入口。

导入歌词默认保存但不接管已有自动歌词。用户在当前歌曲的“歌词来源”区域选择“本地歌词”后才会启用；可随时选择“自动歌词”，不会删除导入文件。自动歌词本来为空时，已保存本地歌词仍会自动回退显示，避免每首云盘歌曲都要额外点一次。

## 歌曲指纹

优先使用可验证的稳定 ID：本地曲库用 `localFileId`，平台歌曲用 `provider + providerSongId`。云盘、聚合或缺失稳定 ID 的歌曲改用归一化标题、主要歌手、专辑和四舍五入时长的 SHA-256 指纹。仅用于本机保存，不上传原始路径或歌词。

## 云盘自动回退与误识别防护

云盘主接口返回空歌词后，使用标题、第一位主要歌手和时长搜索少量网易候选。候选必须同时满足：

- 标题归一化后完全相等，或严格的去副标题等价；
- 主要歌手存在交集；
- 双方时长必须存在，且差值不超过 3 秒；
- 最高分与第二名至少相差 15 分。

任何一个条件不足、候选歌词为空、出现并列候选或请求失败，均视为“未验证”，不写自动缓存、不替换当前画面，并显示手动导入入口。自动匹配成功会以“已验证自动匹配”来源写入独立指纹缓存，不会污染 endpoint 缓存。

## 用户界面

在播放器既有歌词操作区域复用“歌词源”分段按钮，并在现有编辑弹窗增加文件导入：

- 显示当前来源：内嵌、同名 LRC、平台、已验证匹配或已导入。
- `导入 LRC…` 只接受 `.lrc`、`.txt`，限制 512 KiB；通过受限 file input 在渲染进程读取 UTF-8 / UTF-16 / GB18030，随后复用已有自定义歌词存储。
- 将现有“原词 / 自定义”明确为 `自动 / 本地歌词`；导入后用户可在这两个来源间切换。
- 若无可用歌词，按钮保持可见，减少用户寻找入口的成本。
- 任何切换立即重解析并渲染；异步读取保留现有 `trackSwitchToken`，旧曲目不能覆盖新曲目。

## 数据与安全

导入歌词沿用已有自定义歌词本地持久化。路径只在导入时用于读取，不保存外部绝对路径；用户可删除单条本地歌词。本轮不把它纳入“安全清理缓存”，以免误删用户主动保存的内容。

## 测试与验收

- 保持侧车歌词优先于内嵌歌词。
- 手动歌词可保存、启用/停用、跨重启读取，并且切歌竞态安全。
- 云盘候选仅在标题、歌手、时长和分差全部达标时缓存；相同标题不同歌手、时长不符和并列候选均拒绝。
- 无有效歌词时显示可导入入口，不伪造“完成”。
- 文件扩展名、大小、空内容、编码和损坏索引都安全失败。
- 执行专项 Node 测试和 `npm run check`；Electron 手动验收仅证明文件选择器与实际渲染，不能替代命令行验证。
