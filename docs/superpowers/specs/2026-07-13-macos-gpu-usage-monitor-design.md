# macOS 显卡占用监视设计

## TL;DR

负载监视器新增与 CPU 行同样布局的“显卡”行，显示 macOS 提供的真实系统 GPU 占用。只有监视器打开时才每 2 秒采样一次；系统不提供指标或读取失败时显示 `--`，不拿 GPU 辅助进程的 CPU 数字冒充。

## 方案选择

1. **`ioreg` 的 `Device Utilization %`（采用）**：不需要管理员权限，当前 Mac 实测约 0.01 秒完成，可得到真实系统 GPU 占用。
2. **Electron GPU 辅助进程 CPU（不采用）**：容易读取，但代表该进程占用 CPU，不是显卡占用，会误导用户。
3. **`powermetrics`（不采用）**：数据完整，但通常需要管理员权限，采样更重，不适合每 2 秒刷新。

## 数据流

1. 新增独立的 macOS GPU 指标模块，执行 `/usr/sbin/ioreg -r -l -d 1 -c IOAccelerator`。
2. 从输出的 `PerformanceStatistics` 中解析所有 `Device Utilization %`，多显卡时取当前最高值，并限制在 `0-100`。
3. `mineradio-device-stats` 在 macOS 上返回 `sysGpuPct`；其他平台或读取失败时返回 `null`。
4. 现有负载监视器沿用每 2 秒拉取一次的节奏，在 CPU 行后增加“显卡”行。

## 性能与异常处理

- 监视器关闭时不执行 `ioreg`，不增加后台常驻采样。
- 命令超时设为 1 秒，输出上限 1 MB，避免系统异常时拖住主进程。
- 同一次采样尚未结束时复用进行中的请求，避免重复创建系统进程。
- 解析不到、命令失败或不是 macOS 时返回 `null`，界面稳定显示 `--`。

## 界面

负载窗口保持现有尺寸、颜色和排版，只在 CPU 行下方新增一行：

```text
CPU   系统 24% · 播放器 6%
显卡  系统 62%
内存  71%(剩余 5.2 GB) · 播放器 430 MB
```

不增加卡片、图标或新颜色，左右标签和数值与 CPU 行对齐。

## 验证

- 测试先覆盖正常解析、多显卡取最高值、非法值钳制和无数据降级。
- 测试主进程只在 macOS 调用读取器，并把 `sysGpuPct` 返回给前端。
- 测试 HUD 包含独立“显卡”行并使用与 CPU 相同的百分比格式。
- 运行 `npm run check`、`git diff --check` 和前端语法检查。
- Electron 实机测试必须使用假摄像头参数；打开负载监视器后确认显卡数字刷新、布局无错位，关闭后不再采样。
