# 独立 WebGL Metaball 雨窗设计

## 目标

恢复 `public/rain-window.html` 作为独立的浏览器预览页，呈现雨滴在玻璃上受重力滑落、留下微珠并融合的效果。页面不接入 Mineradio 主界面、不修改既有“雨境”预设，也不新增网络资源或第三方依赖。

## 范围与边界

- 保留独立控制面板：雨滴密度、雨滴尺寸、雨滴流速、背景模糊，以及本地图片上传。
- 默认背景由页内 Canvas 生成雨夜光斑；上传图片仅在本地 WebGL 纹理中使用，不上传或持久化。
- 使用原生 WebGL 1，兼容 Electron/Chromium；缺少 WebGL 或着色器编译失败时，在页面显示可复制的错误信息。
- 此阶段不改 `public/js/modules/02-visual/18-rain-mood.js`，也不将原型列为产品预设。

## 渲染架构

每帧按以下顺序执行：

1. 背景通道将原始背景绘制并生成可调模糊纹理。
2. 场通道将所有活动雨滴以加法混合写入受限分辨率的场纹理。相邻液滴的能量核相加，形成连续 Metaball 液面，而不是各自独立的圆形。
3. 合成通道读取场纹理的局部梯度，计算玻璃水滴法线；液滴内部采样清晰背景做折射与轻微色散，边缘混入模糊背景、Fresnel（菲涅尔）反射和高光。

为控制显存和发热，场纹理按显示尺寸的 0.65 倍创建，最大为 1440 x 900；背景模糊纹理按设备像素比上限 1.5 创建。窗口缩放时删除并重建旧纹理和 framebuffer（帧缓冲）。

## 粒子行为

JS 只维护有限粒子池，不做逐像素物理。雨滴具有位置、速度、半径、质量、附着时间、蜿蜒种子和透明度：

- 新滴以静止微珠为主，满足半径与附着条件后开始滑落。
- 滑落阶段受重力、阻尼和位置相关的横向噪声驱动；大滴以固定间隔生成少量残留微珠。
- 两滴相交时按质量守恒合并，保留质量加权的位置和速度；合并后的速度短暂提升。
- 达到页面外、透明度过低或超出池容量时回收。

JS 合并保证物理状态合理，GPU 场纹理保证相交到完全合并之间视觉连续。

## 交互与状态

滑条的 `input` 事件立即更新内存参数，不写入 localStorage。背景上传使用 `URL.createObjectURL`，图片纹理上传后立刻释放 URL。页面加载时预生成一批雨滴，使首屏无需等待生成器积累。

## 错误处理

- WebGL 上下文创建失败、着色器编译/链接失败、framebuffer 不完整时，停止渲染并展示错误面板。
- `webglcontextlost` 时阻止浏览器默认处理并显示恢复提示；`webglcontextrestored` 时重建所有程序、缓冲区与纹理。
- 所有画布大小取 `clientWidth/clientHeight` 的最小 1 像素值，避免隐藏或初始布局时创建 0 尺寸纹理。

## 验证

- Node 静态测试断言独立页包含三段通道、Metaball 场纹理、折射/菲涅尔逻辑、动画循环、各控制项和上下文恢复事件。
- 浏览器自动化加载 `rain-window.html`，确认无控制台错误、Canvas 非空，并截图检查首屏确实绘制出背景和水滴。
- 人工检查密度、尺寸、流速和模糊滑条，以及图片上传；观察两滴接触处是否平滑融合、滑落轨迹是否留有微珠。

## 非目标

- 不承诺真实流体求解或跨帧 Navier-Stokes 模拟。
- 不将实验页自动加入产品菜单、打包入口或公开发布。
- 不引入 Three.js、外部图片、CDN 或新的 npm 依赖。
