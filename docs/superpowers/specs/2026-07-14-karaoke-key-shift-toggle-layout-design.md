# Mineradio K 歌升降 Key 与启动开关对齐设计

## 目标

在唱歌模式中增加 K 歌常用的升 Key / 降 Key。调整只改变歌曲、伴奏和原唱音轨的音高，不改变播放速度，也不处理麦克风中的用户声音；实时分离与 AI 双轨分离都必须生效。同时修复高级设置中“启动自动播放”和“秒启动跳过启动页”没有稳定排在同一行的问题。

## 已确认交互

- Key 范围为 `-6` 到 `+6`，每次调整 1 个半音，`0` 表示原调。
- 唱歌面板使用减号、当前 Key、加号组成紧凑的三段控制，左右尺寸对称。
- 调整后立即生效，不暂停歌曲、不改变当前播放进度和倍速。
- 退出唱歌模式后音频立即恢复原调，但保留用户最后选择的 Key；本次应用运行期间重新进入唱歌模式时再次应用该 Key。
- 实时分离和 AI 分轨切换时保留相同 Key。
- 麦克风只继续驱动视觉，不进入变调处理链。

## 技术方案

### 采用方案：SoundTouch AudioWorklet

使用 `@soundtouchjs/audio-worklet` 2.1.0 的自包含处理器文件，并保留其 MPL-2.0 许可说明。主线程使用原生 `AudioWorkletNode` 接入，不引入打包器。

- Key 为 `0` 时完全旁路处理器，不增加常驻音频计算。
- Key 非 `0` 时，在人声/伴奏完成分离和混音后接入一个 SoundTouch 节点，再进入现有分析器与主增益。
- 实时模式只运行一个变调节点；AI 模式先混合伴奏和人声，再运行同一个变调节点，不为两条音轨分别计算。
- 现有倍速使用媒体元素 `playbackRate`。变调启用时关闭浏览器自带保调，并把同一倍速传给 SoundTouch，由其补偿倍速带来的音高变化，再叠加用户选择的 Key。
- 变调模块首次加载失败时保持原声播放、回到 `0 Key` 并提示，不让音频链静音或中断。

### 未采用方案

1. 只修改媒体元素 `playbackRate`：音高和速度会一起变化，不符合 K 歌需求。
2. 先解码整首歌再离线变调：首次等待时间长、内存占用高，也不适合网络流和即时切歌。
3. 自行实现相位声码器：开发和听感风险高，现有成熟实时处理器更合适。

## 音频链

### 实时模式

`歌曲源 -> 实时人声/伴奏处理或直通 -> Key 变调或直通 -> 分析器 -> 主增益 -> 扬声器`

### AI 模式

`伴奏轨 + 人声轨 -> 双滑块增益 -> 混音 -> Key 变调或直通 -> 分析器 -> 主增益 -> 扬声器`

变调节点的创建、参数更新和销毁由独立的小型辅助函数管理。切换 Key 时沿用现有 12ms 淡出和 20ms 淡入保护，避免重接音频图产生爆音。

## 启动开关布局

- 桌面宽度下，“启动自动播放”和“秒启动跳过启动页”固定为同一行两列。
- 两项等宽、等高、文字与状态圆点对齐，列间距保持一致。
- 只在设置面板实际可用宽度不足时切成单列，不根据整个应用窗口的宽度误判。
- 不修改开关功能、状态保存和现有玻璃质感。

## 验证

- 自动测试覆盖 `-6 / 0 / +6` 边界、每次 1 Key、0 Key 旁路和加载失败回退。
- 自动测试覆盖实时模式与 AI 混音模式都经过同一个变调节点，麦克风不接入变调链。
- 自动测试覆盖倍速与变调同时使用时的参数同步。
- 界面测试确认 Key 控件左右对称，两个启动开关在常用设置面板宽度下同一行且等高等宽。
- Electron 使用独立用户资料和假媒体参数运行，不调用真实摄像头或麦克风。
- 运行完整 `npm run check`、相关脚本语法检查和 `git diff --check`。

## 不做

- 不对用户麦克风实时修音或变声。
- 不增加自动识别歌曲原调。
- 不把 Key 范围扩展到超过正负 6，避免极端音质失真。
- 不修改 AI 分轨模型、缓存格式或分轨算法。
