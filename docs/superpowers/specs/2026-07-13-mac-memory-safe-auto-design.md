# Mac 安全定时内存释放设计

## TL;DR

Mac 的“系统级定时释放”改为真正可用，但播放音乐时绝不执行 `/usr/sbin/purge`。播放中只在窗口隐藏后做播放器自身的轻量清理，并把系统级清理记为待处理；歌曲暂停、结束或出错且窗口处于后台后，再补做系统级清理。

## 目标

- “系统级定时释放”在 macOS 上可开启，继续受间隔和内存占用阈值控制。
- 音乐播放时不暂停、不静音、不调用系统级 `purge`，避免噗声、短暂断音和系统负载尖峰。
- 播放中达到清理条件时，只执行现有播放器软清理；系统级清理延期到暂停或结束后的后台时机。
- “需要时请求管理员”关闭时，缺少权限只返回提示，不弹密码框；开启时才允许弹 macOS 管理员授权。
- 手动“系统释放”和“提权释放”继续分别对应不弹授权与允许弹授权。

## 方案选择

1. **分级清理（采用）**：播放中只软清理播放器，系统级清理延期。不会打断音乐，也符合降低发热和卡顿的目标。
2. **播放中淡出后执行系统清理（不采用）**：播放进度不停，但会短暂变小或无声，系统级清理仍可能阻塞音频线程。
3. **播放中直接执行系统清理（不采用）**：无法保证无噗声，且可能造成 CPU、磁盘和内存重新加载尖峰。

## 状态与流程

- 渲染进程在播放、暂停、结束和错误事件后，把当前是否正在播放同步给 Electron 主进程。
- 定时器达到间隔后先读取 Mac 内存占用；低于阈值时保持现有跳过逻辑。
- 高于阈值且正在播放：调用播放器软清理，记录 `pendingSystemPurge`，不调用 `purge`。
- 高于阈值且没有播放：仅在窗口隐藏、最小化或不可见时执行系统级清理。
- 暂停后如果窗口仍在前台，只保留待处理状态；用户隐藏窗口后，由现有深后台触发补做。
- 系统级清理完成后清除待处理状态；失败时保留结果供面板显示，下一次合法间隔再尝试。

## 管理员权限

- Mac 仍先尝试已有的免密 `sudo -n /usr/sbin/purge`。
- 免密失败且“需要时请求管理员”关闭：返回 `needAdmin`，不调用 `osascript`，因此不弹密码框。
- 免密失败且开关开启：才使用 `osascript` 请求 macOS 管理员权限。
- 默认两个开关均关闭，不会自行清理或自行弹管理员窗口。

## 测试与验收

- 自动测试：Mac 自动清理可开启；播放中只软清理并延期系统清理；未播放时才调用系统清理。
- 自动测试：管理员开关关闭时不调用 `osascript`，开启时才调用。
- 自动测试：播放状态通过 preload 和播放事件同步到主进程。
- 运行 `npm run check`、前端语法检查和 `git diff --check`。
- 真机验证：后台播放时达到条件不暂停、不静音、不噗声；暂停并隐藏后才执行系统级清理。

## 回滚

本任务使用独立分支和独立 commit（代码存档点）。如定时清理行为不符合预期，可单独回滚本任务，不影响 PR #31 的唱歌模式省电优化。
