# 壁纸鼠标视差与 Scene 预览恢复设计

## 目标

本批只处理三个互相关联的壁纸体验问题：为 Mineradio 本地图片/视频壁纸增加可关闭的轻量鼠标视差；让 Windows Scene 详情在 MJPEG 单客户端冲突时仍显示真实静态缩略图并可重试；把 Scene 导出完成后的“保存 MP4 到文件夹”和“应用 MP4 到 Mineradio”放在同一操作行。

## 第一性原则分析

1. Wallpaper Engine 的多层深度脚本不会随图片或 MP4 导出到 Mac，因此 Mac 端不能承诺真正的 Scene 分层视差。可可靠实现的是对已应用的本地图片/视频做 GPU `translate3d` 加轻微放大，形成二维平移视差。
2. “封面鼠标视角”只属于歌曲封面背景。壁纸视差必须是独立设置，不能改写该开关，也不能在非本地媒体背景上误生效。
3. Windows `/api/live/<scene>` 是单客户端流。切换 Scene 时必须先断开旧 `<img>`，立即展示列表返回的静态 `previewUrl`，等待旧连接释放后再接入新流；失败时保留静态图，而不是显示破图。
4. Scene 完成态的两个 MP4 动作属于同一决策层级，应共享一个操作容器；运行状态与错误说明继续独立放在下方。

## 交互与状态

### 壁纸鼠标视差

- 设置名称为“壁纸鼠标视差”，默认关闭，放在背景媒体相关设置中，和“封面鼠标视角”并列但语义分离。
- 仅当当前背景来源是已上传或已导入到 Mineradio 本地库的图片/视频时生效；歌曲封面、纯色和无媒体状态不生效。
- 鼠标移动只更新目标值。临时 `requestAnimationFrame` 循环把当前值平滑靠近目标，收敛后停止，不增加常驻帧循环。
- 图片和视频使用同一组 CSS 变量；以轻微额外缩放预留平移边界，避免露出背景边缘。
- 关闭开关、清除壁纸或切换到不支持的背景时，立即回到中心并停止待执行动画。
- 设置随常规设置持久化，并进入 DIY 存档、导入和导出。

### Scene 预览

- 选中 Scene 后先递增选择令牌并移除旧 MJPEG `<img>` 的 `src` 和节点。
- 如果有 `previewUrl`，立即显示真实静态缩略图；没有则显示明确占位，不显示浏览器破图。
- 短暂释放等待后，在令牌仍匹配当前选择时创建新的 MJPEG `<img>` 并挂载 `liveUrl`。
- `load` 后切换为“Windows 实时预览”；`error` 或服务冲突时删除失败流节点、保留静态缩略图，并显示“实时预览被占用或暂不可用”和“重试实时预览”。
- 自动尝试次数有上限；手动重试开启一轮新尝试。切换项目、关闭详情或关闭壁纸库都会使旧令牌失效。

### Scene 完成态操作

- 完成状态的操作行顺序为：时长、保存 MP4 到文件夹、应用 MP4 到 Mineradio。
- 窄宽度允许整行自然换行，不遮挡状态文案。
- 应用中的下载、完成或失败说明继续显示在操作行下方；不得重复提交同一应用任务。

## 验证

- 静态回归测试覆盖：新开关默认值、持久化、DIY 归档、设置入口、独立于封面开关、图片/视频变换与复位。
- Scene 回归测试覆盖：静态预览先显示、旧流先释放、延迟接流、旧选择令牌失效、失败保留缩略图、有限重试和手动重试。
- 完成态测试覆盖两个 MP4 按钮位于同一 `.wallpaper-export-controls`。
- 运行专项测试、完整 `npm run check`、相关脚本语法检查和 `git diff --check`。
- Windows 服务在线时额外执行 `/api/ping`、`/api/live-status` 与实际 Scene 预览对抗检查；若单客户端被其他程序占用，只声明降级状态验证通过，不冒充实时画面已加载。

## 不在本批范围

- 不新增或修改 Windows HTTP 接口。
- 不把图片/MP4 描述成真正的 Wallpaper Engine 分层 Scene。
- 不改变现有 Windows 壁纸批量导入、搜索、筛选、排序和本地缓存逻辑。
