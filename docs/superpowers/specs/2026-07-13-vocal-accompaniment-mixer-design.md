# 唱歌模式伴奏与人声双滑块设计

## TL;DR

唱歌模式把原来的单个“原唱”滑块改为并排语义一致的“伴奏”和“人声”两条滑块。现有频谱处理一次拆出伴奏估计与人声估计，再按两个滑块混合；既能去人声，也能去伴奏保留人声，不增加第二套 FFT 计算。

## 目标

- 伴奏和人声音量均可在 0% 到 100% 独立调节。
- 默认保持伴奏 100%、人声 0%，延续现有唱歌模式行为。
- 伴奏 100%、人声 100% 时直接播放原声，绕过 AudioWorklet，保持 PR #31 的省电行为。
- 加强现有去人声强度，减少带少量立体声扩散的人声残留，同时保留 130Hz 以下贝斯和底鼓。
- 不增加 AI 模型、网络下载或第二个音频处理线程。

## 方案选择

1. **同一频谱掩码双路混音（采用）**：`mask` 作为伴奏占比，`1-mask` 作为人声占比，输出系数为 `伴奏音量 × mask + 人声音量 × (1-mask)`。只增加少量乘加。
2. **同时运行两套处理器（不采用）**：容易产生延迟错位，FFT 开销翻倍并增加发热。
3. **AI 实时分轨（不采用）**：分离更强，但模型体积、延迟、内存和持续算力不适合当前无风扇 Mac 优化目标。

## 音频处理

- 保留现有 STFT、Hann 窗、重叠相加和时间平滑。
- 中置判断曲线从 `ratio^1.4` 加强为更陡的曲线，降低带轻微立体声混响的人声残留。
- 130Hz 以下固定归入伴奏，保护贝斯与底鼓；人声独听模式不会带入这部分低频。
- Worklet 接收 `{ accompaniment, vocal }`，滑块移动时只发参数，不重建音频图。
- 无 Worklet 时，现有中置消除链拆成“伴奏估计”和“原声减伴奏”的人声估计，保持双滑块可用。

## 生命周期

- 只有唱歌模式开启且两个滑块不是同时 100% 时才需要分离处理。
- 从双 100% 跨到其他组合时，沿用现有防爆音淡出/重建/淡入；分离范围内调节不重建。
- 关闭唱歌模式始终恢复原声直通。
- 麦克风启停规则保持 PR #31 的行为，不因双滑块改变。

## 界面

- 唱歌模式弹层保留现有宽度、字体、间距和玻璃样式。
- 第一行“伴奏”，第二行“人声”，两行使用相同列宽，百分比右对齐。
- 提示文案改为“伴奏 0% 可突出人声；人声 0% 可压低原唱”，不承诺 AI 级完全分离。

## 测试与验收

- 自动测试：双 100% 直连；任一滑块低于 100% 才创建分离链；只跨直通边界时重建。
- 自动测试：Worklet 参数同时包含伴奏和人声；混音公式在伴奏模式、人声模式和原声模式下正确。
- 自动测试：加强后的掩码对中置偏移人声比旧曲线衰减更强，纯侧声伴奏仍保留。
- 自动测试：界面存在两条对称滑块，默认伴奏 100%、人声 0%。
- 运行 `npm run check`、相关前端语法检查和 `git diff --check`，再用真实歌曲听感验收。

## 回滚

本任务使用独立分支和独立 commit（代码存档点）。如双滑块听感不满意，可单独回滚到 PR #32，不影响 Mac 内存开关与此前省电优化。
