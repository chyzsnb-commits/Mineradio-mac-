# 最近播放滚动性能与 GPU 文案设计

## TL;DR

最近播放列表滚动时，临时把背后的 3D 场景限制到 30 FPS，把 GPU 合成时间让给列表；停止滚动约 240ms 后立即恢复原帧率。列表自身增加独立合成和滚动隔离，玻璃背景、首页无限悬浮动画和卡片视觉保持不变；负载监视器的“显卡”文字改为“GPU”。

## 目标

- 触控板、鼠标滚轮和拖动滚动条时，最近播放列表明显更跟手。
- 仅滚动期间降低背景 3D 帧率，结束后自动恢复用户原设置。
- 不关闭首页无限悬浮动画，不降低玻璃模糊，不减少最近播放条目。
- 不影响其他歌单、歌词、搜索和 3D 歌单架滚动。
- 负载监视器保持 CPU → GPU → 自适应 → 内存的对称顺序。

## 方案选择

1. **滚动期间让出 GPU（采用）**：最近播放滚动时把 3D 主循环上限设为 30 FPS，并隔离滚动层。只在用户需要 UI 流畅时降载，视觉恢复快。
2. **永久降低首页玻璃模糊（不采用）**：能减少合成开销，但会破坏用户认可的玻璃质感。
3. **减少最近播放数量（不采用）**：30 条 DOM 并不是主要开销，且会损失功能。

## 实现

- 最近播放列表监听 `wheel` 和 `scroll`，记录活动截止时间 `now + 240ms`。
- 滚动开始时增加 `is-scrolling` 类；停止后移除。滚动期间关闭卡片位移和阴影过渡，避免指针下方卡片反复重绘。
- 列表增加 `overscroll-behavior: contain`、`contain: layout paint`、`will-change: scroll-position` 和独立合成层。
- 主循环在 `isHomeRecentScrollActive()` 为 true 时返回不高于 30 FPS 的 3D 目标；用户原本选择 24 FPS 等更低档位时继续尊重更低值。
- 不调用全局交互增压，避免滚动反而把粒子、歌词和音频分析提升到高频。

## 测试与验收

- 自动测试：HUD 使用“GPU”且顺序保持在 CPU 与内存之间。
- 自动测试：最近播放绑定滚轮和滚动事件，活动窗口为 240ms。
- 自动测试：滚动活动时 3D 上限为 30 FPS，24 FPS 用户设置不被提高。
- 自动测试：CSS 包含滚动隔离，并保留首页玻璃 `backdrop-filter`。
- 运行 `npm run check`、前端语法检查和 `git diff --check`。
- Electron 真机检查滚动前后 FPS 自动恢复、面板无错位、文字无溢出。

## 回滚

本任务使用独立分支和独立 commit（代码存档点）。如临时降帧观感不合适，可单独回滚滚动优化，不影响 PR #33 的唱歌模式双滑块。
