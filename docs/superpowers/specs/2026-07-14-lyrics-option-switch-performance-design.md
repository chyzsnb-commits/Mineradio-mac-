# 歌词选项切换卡顿优化设计

## 目标

优化“歌词行数”“双语翻译”“歌词动画”三组按钮的切换卡顿。保持按钮外观、歌词视觉效果和设置持久化行为不变，让按钮立即响应，并避免每次点击都同步重建完整 3D 歌词轨道。

## 根因与基线

三个按钮当前都会调用 `refreshStageLyricDisplayMode()`，该函数通过 `showStageLine(payload, true)` 立即销毁当前歌词网格并同步调用 `buildLyricMesh()`。重建过程包含 Canvas 文字绘制、多层模糊光晕、纹理创建和 GPU 上传，全部发生在渲染主线程。

在 Electron 隔离测试资料和 90 行双语歌词下：

- 完整五行双语轨道生成 180 个歌词行网格，同步构建约 83ms。
- 现有轻量轨道只生成 18 个歌词行网格，同步构建约 11.6ms。
- 一次完整轨道首次渲染的压力测试出现约 2.15 秒 GPU 提交停顿，符合用户所说的“卡几下”。

## 方案

### 行数与翻译

1. 点击后立即更新按钮选中状态、内存设置、保存任务和提示文字。
2. 不在点击事件里同步构建完整轨道；把歌词刷新安排到下一帧，并合并连续点击，只处理最后一次选择。
3. 多行模式先使用项目已有的 `lightweightTrack` 轻量轨道，只生成当前附近需要显示的行；单行模式继续只生成当前行。
4. 新轻量网格生成完成前保留旧歌词，不出现空白或闪烁；生成后一次替换。
5. 浏览器空闲后再调用现有完整轨道预热逻辑，为后续连续播放准备完整窗口。

### 歌词动画

“漂浮 / 柔滑 / 玻璃 / 线光 / 故障”只改变运动参数和着色器参数，不改变歌词文字或行布局。切换时直接更新当前歌词及过渡歌词的运动类型和着色器 uniform（运行参数），不销毁 Canvas、纹理、材质和网格。

需要原地更新的参数包括扫光、闪烁、故障强度、故障切片、色差、故障速度和边缘亮度。进入或退出故障模式时同步重置故障瞬时状态，避免残留。

## 边界处理

- 点击已经选中的选项时直接返回，不重复保存、提示或刷新。
- 快速连续点击时取消上一项待执行刷新，只应用最终选项。
- 没有正在显示的歌词时只保存设置，不创建无用网格。
- 轻量刷新失败时保留旧歌词并安排一次现有完整刷新，不让歌词消失。
- 不修改字体、玻璃质感、歌词配色、音频播放、桌面歌词和其他视觉系统。

## 验证

- 新增回归测试，确认三组按钮跳过重复选择、行数和翻译使用合并后的轻量刷新、动画采用原地更新。
- 运行 `npm run check`，确认现有 69 项检查和新增检查全部通过。
- Electron 使用隔离资料与假媒体参数，重复切换三组按钮并记录同步耗时、下一帧耗时和 `lyrics.mesh-build` 次数。
- 验证动画切换的 `lyrics.mesh-build` 为 0；行数和翻译使用轻量轨道，完整轨道只在空闲预热。
- 检查快速连点最终选项正确、歌词不中断、运行日志无报错。
